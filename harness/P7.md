# P7 比赛演示系统实施与验收计划

## 目标
交付可重复启动和展示的比赛演示系统：固定模拟数据库、钢厂采购/回收商购销/自然人销售三个完整流程；验证预测来源与模型版本、供需与交易优化、额度规则、Agent 多轮上下文；完成后端/前端/端到端及 Docker 可执行性检查；形成架构、部署、演示、模型评估和验收文档。

## 范围与边界
- 固定 seed、模拟器版本、业务日期和数据库文件；业务数据重建必须一致，测试在独立临时 DB 上运行。
- 预测只能报告可加载模型的真实运行结果；模型依赖或制品缺失则演示模型不可用状态和来源证据，不生成替代数值。
- 完成三类角色 API/优化/额度/对话测试和可机器读取的验收报告。
- 建立 API 与 Web 容器、Compose 健康检查和容器内存活测试。当前 API 使用 SQLite；不得将 Compose 写成已支持 PostgreSQL 的业务部署。
- 浏览器 E2E 需有可用浏览器驱动；Docker 测试需本机安装 Docker Engine/Compose。缺环境要记录为未执行并给可复制命令。

## 计划步骤
1. 基线盘点：依赖、模型制品、数据版本、测试、端口、Docker 和浏览器工具状态。
2. 固定比赛数据库与场景参数，修复重复生成、测试污染或业务阻断问题。
3. 为预测记录补模型版本/数据哈希/训练窗/计算依据来源；跑真实可用的预测训练与评估，报告失败原因。
4. 增加钢厂采购、回收商购销、自然人销售的固定场景和端到端回归，多轮会话、额度及约束断言。
5. 增加 Docker 构建/Compose 编排与健康检查；实测可用部分，不谎报无法执行的容器测试。
6. 执行后端、前端、E2E、Docker 测试，整理架构说明、部署手册、比赛演示脚本、模型评估及 P7 验收报告。

## 验收门
- 相同种子和参数产生相同业务数据快照，三类角色场景结果重复运行一致。
- 自然人不能采购，年度模拟额度不超 500 万且不得重复占用；撮合/优化输出包含约束与来源。
- 预测每个数值都有模型/规则版本、来源、截止日期、目标周期及可追溯数据版本；不可用则没有数值。
- 后端和 Web 静态/单测通过；真实端到端链路通过。Docker Compose 若环境具备则启动并健康检查。
- 所有未通过/未执行项在报告中明确，不得作为已验收。
